# 艾瑟兰战役 · 变量与数据AI 管线

> 面向：维护脚本的人、接手改动的 AI、想知道"数字到底存在哪、谁在改"的玩家。
> 本文是**实现说明书**：讲清每一份数据存在哪、谁读谁写、数据AI 每回合到底收到什么、错误怎么兜。
> 设计意图（为什么这么设计）见战役设计目录里的《变量设计.md》；本文以**代码现状**为准（v1.0.6）。

---

## 0. 一句话

存档放在酒馆聊天变量 `艾瑟兰` 里，是**唯一事实源**；每回合由脚本把正文交给"数据AI"翻译成一份**增量变更包**，脚本校验后结算写回存档，再同步一份快照到楼层变量，供状态栏（以及将来的 EJS 世界书条目）读取。

**铁律：数字只被脚本改。** 正文 AI 与数据AI 都不做算术、不直接改存档。

---

## 1. 五份数据，别搞混

| 存在哪 | 内容 | 谁读 | 谁写 | 生命周期 |
|---|---|---|---|---|
| chat 变量 **`艾瑟兰`** | 完整存档（本文第 2 节全部字段，含每轮清空的 `动作` 流水） | 脚本（`core/store.ts`） | 脚本 | 换聊天自动隔离；「重置存档」手动清 |
| message 变量 **`stat_data.艾瑟兰`** | 存档快照，**剥掉 `时刻.累计分钟`** | 状态栏 HTML、（待做）EJS 世界书条目 | 脚本 `syncSnapshot()` | 每回合同步到最新楼 + 开局时写第 0 楼 |
| chat 变量 **`艾瑟兰日志`** | 上一回合的结算日志：动作行、被丢弃的条目、错误 | 「战役」页展示 | 脚本 | 每回合覆盖 |
| extensionSettings **`艾瑟兰战役`** | 设置：自动结算开关、状态栏标记、数据AI 频率、API 配置、提示词分段 | 「战役」页 /「战役·提示词」页 /「API」页 | 面板 | 跟酒馆设置走 |
| 内存（不落盘） | 忙碌标志（防重入）、回合计数 | 调度器 | 调度器 | 关页面即失 |

> ⚠️ 状态栏与 EJS 条目**只读快照，永不写档**；玩家操作（确认推演等）走 chat 变量通道（手操功能尚未实现）。

## 2. 变量总表

### 2.1 时刻

| 字段 | 类型 | 默认 | 谁改 | 说明 |
|---|---|---|---|---|
| `时刻.当前时刻` | 字符串 `"1042年11月29日 14:20"` | 开局值 | 数据AI（唯一必填字段） | 格里高利历；脚本按它与存档中的时刻算 Δt |
| `时刻.累计分钟` | 整数 | 0 | 脚本 | **内部账本**：算力恢复、临时加成倒计时、陷落度自动推进都按它算；快照里被剥掉，AI 永不可见 |

Δt 防呆：`< 0` 按 0（AI 报了个更早的时刻）；`> 720` 封顶 720 分钟（防 AI 一觉睡三天）。

### 2.2 位置

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `位置.当前` | 自由文本 | `"审判广场"` | 具体地点，如"灰石集市·工坊区通风管道" |
| `位置.区域` | 枚举 `下层/中层/上层/城外` | `下层` | 与沙盘四层结构对齐；枚举校验，越界丢弃 |

### 2.3 时钟

| 字段 | 范围 | 推进方式 | 说明 |
|---|---|---|---|
| `时钟.维尔伦陷落度` | 0–6 | **脚本**每累计满 240 分钟自动 +1；数据AI 另可申报事件增量 | 两者同回合叠加，不封顶（钳到 6） |
| `时钟.教会肃清进度` | 0–3 | 纯数据AI 申报 | 只增不减（契约层 min(1)，负数进不来） |

### 2.4 算力

| 字段 | 默认 | 说明 |
|---|---|---|
| `算力.当前算力` | 0 | 存量；每回合 `+Δt×速率/60`，封顶 `20×基础智力`，溢出作废 |
| `算力.速率` | 10 | 每小时恢复点数；第一卷恒定，留作后续卷的修改口 |
| `算力.累计消耗` | 0 | 只增不减；≥100 世界【异象】、≥250 世界【裂隙】 |
| `算力.推演记录` | `[]` | `[{名称, 档, 实付算力, 时刻}]`，成交时追加，供状态栏/卷末回顾 |

> **算力不给数据AI看**（它不做算术，推演只报名称与档位，费用与阈值一律脚本裁决）。算力是给玩家看的资源：正文AI 通过 EJS 注入看到"当前算力 45/220"，从而能自己编出"算力不足"的回应。

### 2.5 物品（一张列表，全档一份 · 编号制 · 不堆叠）

| 字段 | 说明 |
|---|---|
| `编号` | **每件物品独立编号**（数字字符串 `"1"`、`"2"`…，取现存最大值 +1）；旧档由 `loadGame` 自动补齐 |
| `名称` | 物品名（不再是唯一标识——**同名多件 = 多条记录**，各占一个编号） |
| `类型` | `装备` / `消耗品` / `材料` / `特殊` |
| `持有者` | 默认 `主角`；可写生物名（如爱丽丝） |
| `描述` | 自由文本 |
| `槽` | **仅装备**有：`武器` / `副手` / `护甲` / `饰品` |

**不堆叠**：不再有 `数量` 字段。三块硝石 = 三条记录（编号 4/5/6）。数据AI 报的 `物品新增` 里仍可写 `数量: 3`，**脚本会展开成 3 条各自编号的记录**；**旧档**里的 `数量: N` 也会在 `loadGame` 迁移时展开成 N 条（不会把三块硝石压成一块）。

**装备槽存编号**：`主角.装备.武器 = "1"` 指向编号 1 那件（显示时由状态栏解析成名字），这样两把同名短剑也能精确区分穿的是哪一把。只有**主角**与**爱丽丝**有装备槽。

> **状态栏界面不显示编号**（编号只是脚本/存档内部用来精确寻址的）：物品、装备槽、可装列表都只显示名称。

**数据AI 侧的物品操作**（名称口径，不必知道编号）：
- `物品新增`：给 `名称/类型/描述/槽`，需要几件就写 `数量`（脚本展开）
- `物品移除`：给名称（或编号）→ **只删一件**
- `物品数量`：负数按名称删 N 件（不足则不动作并记日志）；正数按同名现有物品为模板复制 N 件（各有新编号）

### 2.6 主角

| 字段 | 类型/范围 | 默认 | 谁改 | 说明 |
|---|---|---|---|---|
| `性别` | 枚举 `男/女` | 男 | 开局面板 | 纯叙事，第一卷无数值影响 |
| `属性` | 力/敏/体/智 各 1–13（智力上限 14） | 8/8/8/11 | 力/敏/体：数据AI（单次 ±2）；**智力：脚本按时间自动成长** | 本卷天花板 13（NPC 不设 13 上限，钳 1–23）；**智力每 10 游戏小时自动 +1，上限 14**，AI 严禁申报智力（报了会被拒收） |
| `临时加成` | `[{属性,值,剩余分钟,来源}]` | `[]` | 数据AI 申报；**脚本**按 Δt 倒计时，到期自动删 | 同一属性多条叠加（战歌+药剂=力+3） |
| `状态` | 自由文本 | `""` | 数据AI（`主角状态` 字段） | 持续性生理状态，如"左肩贯穿伤(失血)""重度致幻(抗毒中)"；恢复良好报 `"健康"`；一过性动作/心理不报 |
| `技能` | `[{名称,等阶,描述}]`，等阶 入门/熟练/精通/大师 | `[]` | 数据AI 新增/提升（阶梯+1）/移除 | 重名不重复添加；已是大师再提升→丢弃该条 |
| `装备` | `{武器,副手,护甲,饰品}` 槽→**物品编号**或 null | 全 null | 状态栏点选（AI 已被禁止申报） | 槽位存编号，显示时解析名称；旧档存名称的由 loadGame 迁移 |
| `精练师等级` | 枚举 无/低级/中级/高级 | 无 | 数据AI | 只在诺拉现场指导协助下首次完成药剂萃取/料理精炼时报"低级"；只升不降 |
| `已解锁知识库` | 字符串数组 | `["地球"]` | 脚本（第一卷锁死） | 契约不开口子，AI 改不了 |

### 2.8 派生量（不存储，用时现算）

| 派生量 | 公式 | 用在哪 |
|---|---|---|
| 算力上限 | `20 × 基础智力`（临时加成的智力不计入） | 存算封顶、状态栏显示 |
| 生效属性 | 基础值 + 同属性临时加成求和 | 状态栏与数据AI 摘要显示"力9"而不是"力8+1" |
| 世界状态 | 累计消耗 <100 微澜 / ≥100 异象 / ≥250 裂隙 | 状态栏徽章、沙盘后果表 |
| 陷落度阶段名 | 0–6 格 → 风暴眼/混乱期/沦陷期/收束期/终局 | 状态栏与摘要的括号文案 |

### 2.9 刻意不入档的东西

马利基真相、暗金圣火目击、逃生路线、卷末带走的人/物资/信息——这些交给正文AI 与记忆插件，脚本不追踪（也就不做路线相关的自动判定，例如"走圣堂裂隙道不推肃清钟"由数据AI 按提示词遵守）。

### 2.10 动作（每轮清空的玩家操作流水）

状态栏上的玩家操作会写进 `动作` 数组；**脚本在每回合开始时清空**（不跨轮），快照里带上，供 EJS 世界书条目注入正文AI。

| 字段 | 说明 |
|---|---|
| `类型` | 动作类别。当前只有 `"使用消耗品"`；后续可扩（推演 / 装槽 / 施法等） |
| `名称` | 物品名或动作名 |
| `编号` | 涉及物品时填物品编号（物品编号制见 §2.5） |
| `说明` | 自由文本（如该物品的描述），供正文AI理解效果 |
| `时刻` | 记录时的游戏内时刻 |

**典型条目**

```json
{ "类型": "使用消耗品", "名称": "治疗药剂", "编号": "2", "说明": "外敷内服都行", "时刻": "1042年11月29日 16:47" }
```

**生命周期**：状态栏点击使用 → 脚本删掉该件物品 + 追加一条 `动作` → 写 chat 变量并同步快照（300ms）→ **正文AI 通过 EJS 世界书条目读到它**（由你自行编写条目，读 `stat_data.艾瑟兰.动作`）→ 下一次回合开始时脚本清空。

**数据AI 也会看到**（状态摘要里有一行"玩家已通过状态栏执行的动作（脚本已处理，你无需再申报）"），避免它把同一件事重复申报一遍；但**数值效果**（回血、临时加成等）目前不由脚本自动施加——需要的话在 EJS 条目里引导正文AI描写，或后续加"效果表"。

## 3. 数据AI 管线

### 3.1 回合时序

```
酒馆产生新 AI 回复（type ∈ normal/regenerate/continue/swipe）
        │
        ├─ 未开局（无 `艾瑟兰` 存档）→ 完全静默，不抢渐变带/开局框架的活
        ├─ busy 防重入；按「数据AI 频率」每 N 条跑一次（未跑则只补楼末标记）
        ▼
  ⓪ 清空动作                       每回合开始先清 `动作`（状态栏操作流水不跨轮）
  ① loadGame()                     读 chat 变量 `艾瑟兰`（zod 校验，坏档忽略）
  ② runDataAI(game)
        ├─ 拼提示词：设置里的分段 + {{状态}}（serialize数据AI）+ {{正文}}（分层正文）
        ├─ callGenerate（json_schema 结构化输出；API 走「API」页配置，默认跟随酒馆）
        ├─ 抽取 JSON（容忍 ```json 包裹与前后废话）
        └─ zod 契约校验 → 通过则给出"变更包"
  ③ settle(game, 变更包)            纯函数，严格按 11 步顺序结算（见 3.4）
  ④ saveGame(新存档)                写回 chat 变量
  ⑤ syncSnapshot()                 剥 `时刻.累计分钟` → 写最新楼 stat_data.艾瑟兰
  ⑥ 写 `艾瑟兰日志`（动作行/丢弃/错误）
  ⑦ 若开关「状态栏标记」开 → 楼末补 `<StatusPlaceHolderImpl/>`（幂等）
```

手动入口：「战役」页的「手动结算一次」（走同一 runTurn）、「重置存档」、「注入开局面板到最新楼」。

### 3.2 数据AI 实际收到的三样东西

**① 提示词（分段可在「战役·提示词」页编辑，默认 5 段）**

| 段 | role | 内容 |
|---|---|---|
| 1 | system | 任务与 13 条铁律（不做算术/只报变化/禁止凭空造物/时刻格式/推演档位/时钟条件/属性条件/临时加成/生物白名单/关系/异界幼体/事件范围铁律） |
| 2 | system | 【当前状态】＝ `serialize数据AI()` 的输出（见下） |
| 3 | system | 【最近正文】＝ 分层正文：**前文背景**（上一轮及更早，只读因果）＋ **本轮待结算正文**（最新一轮，唯一提取源） |
| 4 | system | 【输出格式示例】＝ 一两个 JSON 形状示例 |
| 5 | user | 收尾指令："只写发生变化的字段" |

每段发出前会做酒馆宏替换（`{{user}}` 等）。

**② 状态摘要（`src/aiselan/pipeline/serialize.ts`）**

原则：**只给"AI 要靠它才能做出正确申报"的信息**。样例：

```
【当前状态】
当前时刻：1042年11月29日 22:40
位置：中层 · 灰石集市·工坊区通风管道
陷落度：2/6（混乱期）｜肃清进度：1/3
主角：力9 敏9 体9 智11，临时：力量+1(战歌,剩120分)
主角状态：轻伤
主角技能：剑术(熟练)
主角装备：武器:精钢短剑
精练师等级：无｜已解锁知识库：地球
物品：精钢短剑×1(装备/武器)、治疗药剂×1(消耗品)、硝石×3(材料)、燃烧瓶图纸×1(特殊)
已遇见人物：爱丽丝(同伴,在队,关系:相识)、诺拉(同伴,留守在通风管道,关系:相识)、维克托(敌对,在广场清点幸存者)
```

刻意**不发**：算力（含上限/速率/累计消耗/世界状态）——AI 不做算术；未遇见的人物（避免它乱报）；不入档的叙事状态。
**额外会发**：若本回合存在状态栏操作，摘要末尾追加一行「玩家已通过状态栏执行的动作（脚本已处理，你无需再申报）：使用消耗品「治疗药剂」（外敷内服都行）」——防止 AI 把已处理的物品消耗再申报一遍。

查看器：`node scripts/show-data-ai-prompt.mjs`（用真实代码拼装，占位符填假数据，随时可导出对照）。

**③ json_schema（结构化输出约束）**

顶层属性：`当前时刻`（必填）、`位置`、`时钟`、`推演`、`属性`（仅力敏体）、`主角状态`、`临时加成新增`、`临时加成移除`、`精练师等级`、`物品新增`、`物品移除`、`物品数量`、`技能新增`、`技能提升`、`技能移除`、`生物`。除 `当前时刻` 外**全部可选**，从 schema 层面逼 AI"只报变化"。

> 与提示词一致的强制约束（schema 层就挡住，不只是靠 AI 自觉）：**属性里没有 `智力`**（智力由脚本接管）、**没有 `装备变更`**（穿脱由玩家在界面手动做）。契约层仍保留这两条通道的口子（供未来手操/脚本自己用），但数据AI 走结构化输出时根本发不出来。

**④ 可用占位符（自己改提示词时能用的变量）**

替换分两步，先脚本、后酒馆：

| 占位符 | 来源 | 展开成什么 |
|---|---|---|
| `{{状态}}` | **本战役脚本** | `serialize数据AI()` 的输出——当前时刻 / 位置 / 陷落度与肃清 / 主角四维与临时加成 / 状态 / 技能 / 装备 / 精练师等级 / 物品 / 已遇见人物（见上面样例） |
| `{{正文}}` | **本战役脚本** | 分层正文——【前文背景】（上一轮及更早）＋【本轮待结算正文】（最新一轮） |
| `{{user}}` | 酒馆宏 | 玩家名字 |
| `{{char}}` | 酒馆宏 | 当前角色卡名字 |
| `{{time}}` / `{{date}}` | 酒馆宏 | 现实时间 / 日期（**不是**剧情内时刻，剧情时刻请用 `{{状态}}` 里的「当前时刻」） |
| `{{persona}}` / `{{description}}` 等 | 酒馆宏 | 其余酒馆自带宏；以你所用酒馆版本支持的宏为准 |

注意：
- **未知占位符不会被替换**，会原样发给 AI（例如把 `{{状态}}` 写成 `{{当前状态}}` 就会原样透传）——改提示词后建议跑一次 `node scripts/show-data-ai-prompt.mjs` 对照。
- 脚本占位符只有 `{{状态}}` 和 `{{正文}}` 两个；`{{正文}}` 已经自带分层标记，不需要再包一层。
- 占位符替换发生在**每段内容**上，与分段的 role / 开关无关；关掉（OFF）的分段整段不发送。

### 3.4 结算顺序（`pipeline/settle.ts`，严格按序）

| # | 步骤 | 规则与钳制 |
|---|---|---|
| 1 | **时间结算** | Δt 防呆（<0→0，>720→720）→ 算力 `+Δt×速率/60` 且封顶 `20×智力` → 临时加成逐条扣 `剩余分钟`（≤0 删）→ 累计分钟累加，每满 240 分钟陷落度 +1 → **每满 600 分钟（10 小时）智力 +1（上限 14）** |
| 2 | 位置 | 区域枚举校验；当前自由文本覆盖 |
| 3 | 时钟申报 | 只接受正增量、只增不减，钳 0–6 / 0–3 |
| 4 | 推演 | 按档定价 10/25/50/150/400；算力够→扣费+累计消耗+写推演记录；**不够→只丢这一条**；累计消耗跨过 250（进入【裂隙】）时**脚本自动给魔物（类型=生物）全属性 +1**，人类 NPC 不受影响 |
| 5 | 属性 | 每项单次 ±2；**`智力` 一律拒收**（丢该字段并记日志，其余属性照常落地）；主角钳 1–13（本卷天花板 13），NPC 钳 1–23 |
| 6 | **主角状态** | 自由文本直接覆盖；`"健康"` 即恢复正常；例："左肩贯穿伤(失血)"、"重度致幻(抗毒中)" |
| 7 | 临时加成 | 新增必须含 属性/值/持续分钟/来源；移除按来源名 |
| 8 | 物品/装备 | `物品新增` 按数量展开成 N 条独立记录（各自编号，不堆叠）；`物品移除` 删一件；`物品数量` 负删正复制（数目不足则不动作）；装备变更按编号/名称校验持有者·类型·槽（**数据AI 已被禁止申报**，由状态栏点选） |
| 9 | 技能 | 新增（重名跳过）/提升（阶梯+1，已是大师丢弃）/移除 |
| 10 | 精练师等级 | 枚举校验，只升不降 |
| 11 | 生物 | 不在建档列表→丢弃；`已遇见` 只能 false→true；`状态` 自由文本；`和主角的关系` 白名单校验；属性增量 ±2 |
| 12 | 写档 + 快照 + 日志 | 见 3.1 的 ④⑤⑥ |

### 3.5 容错策略（重要）

| 情况 | 处理 |
|---|---|
| API 报错 / 返回空 | 记错误到日志，本回合不结算（存档不动） |
| 抽不出 JSON | 同上（整包丢弃） |
| JSON 能抽出但**整包不符合契约**（如时刻格式错） | 整包丢弃，日志记录前三条 zod 报错 |
| **单条语义非法**（未建档生物、关系值不在白名单、技能不存在、装备槽不匹配、推演算力不足、区域枚举越界） | **只丢该条**，其余照常落地，日志记"丢弃"行 |
| AI 报负数时钟 / 非法档位 | 丢弃该条 |
| AI 报 `智力` 变动 | 丢弃该字段并记日志（智力由脚本接管），同包其它属性照常结算 |
| AI 报 `装备变更` | 结构化输出层就发不出来（schema 无此字段）；若绕过则照旧校验落地 |
| `物品数量` 要求删/复制但同名物品不足 | 不动作并记日志（不产生"凭空多出/少掉"的物品） |
| AI 报了契约外的新字段 | **静默忽略**（zod 默认行为，不报错） |

### 3.6 快照与消费侧

- `syncSnapshot()` 深拷贝存档 → 删 `时刻.累计分钟` → 写最新楼 `stat_data.艾瑟兰`
- 状态栏 HTML 读快照时按 **当前楼 → -1 → -2 → -3** 回退查找，再回退读 chat 变量（只读）
- 状态栏显示：时刻/位置/世界状态徽章、陷落度 6 格与肃清 4 格（含阶段名）、算力条与累计消耗刻度、主角属性（含临时加成）与装备技能、**已装备（主角四槽）**、物品四类、已遇见人物（同伴/敌对分组，死亡灰显，同伴显示关系）
- **状态栏可写（装备穿脱 + 使用消耗品 + 删除物品）**：消耗品行点「使用」→ 删该件 + 记一条 `动作`（§2.10），供 EJS 注入；**删除物品要先开「删除模式」**（物品区标题旁的开关；开启后每件物品旁才出现「删除」，点了即刻移除、**无二次确认**；删除正被穿着的东西会同时清空对应槽位）；**物品区可折叠**（标题旁「折叠/展开」，折叠后只显示 `装备×N　消耗品×N　材料×N　特殊×N` 摘要，防止后期条目膨胀）；**主角**（独立的「已装备（主角）」区块）与**爱丽丝**（她的人物卡内）都能点「装备」/「卸下」，走 `writeGame` 写 chat 变量 + 300ms 后同步快照再就地重渲染；纯函数 `装备物品(存档, 编号, 人物)/卸下装备(存档, 人物, 槽)` 只认**本人持有**的「装备」类物品且**槽位必须匹配**（不合规不落盘）；物品一律带 `#编号` 显示，同名多件也能精确点选
- **EJS 世界书条目（待做）**：读快照翻译成人话注入正文AI（正文AI 只看描述、不看公式，且算力对它是可见的）

## 4. 数据AI 提示词的 14 条仲裁铁律速查

提示词分段：①任务目标与 14 条铁律（system）②【当前状态】（system）③分层正文（system）④格式与 Few-Shot 四场景（system）⑤收尾严格警告（user）。

| # | 归类 | 规则要点 |
|---|---|---|
| — | 至高准则 | **字面事实原则**：唯一事实源是【本轮待结算正文】；严禁脑补；【前文背景】只用于核对因果 |
| 1 | 运算底线 | 绝不做任何算术（算力加减/恢复、加成倒计时、陷落度时间累加全归脚本） |
| 2 | 运算底线 | 只报变化、极度克制；日常交谈/普通移动 → 只输出一行 `{"当前时刻": "..."}` |
| 3 | 运算底线 | 不凭空造物与夺物：`物品新增` 需明确获取动作（并给 `槽`）；`物品移除`/`物品数量` 仅在实际消耗/丢失/投掷/损坏时；**严禁申报 `装备变更`**（穿脱由玩家在界面手动做） |
| 4 | 运算底线 | 只输出一个合法 JSON；schema 外的顶层字段被系统直接丢弃 |
| 5 | 时空推进 | `当前时刻` 唯一必填，格式 `YYYY年M月D日 HH:MM`；按情节推断耗时（交谈 3~10 分、潜行翻找 15~30 分、战斗 5~15 分、包扎休整 1~2 小时），只能向前 |
| 6 | 时空推进 | 位置只在明确位移时更新；区域只能取 下层/中层/上层/城外 |
| 7 | 战役时钟 | 陷落度 +1：全城级大动静（剧烈爆破/大面积坍塌/大规模混战），**普通战斗不报**；肃清 +1：在教会卫兵面前公开用系统技术、与审判庭猎杀小队交火、被大批平民目击报告教会（特例：走大教堂地脉通道潜行出城不报） |
| 8 | 科技推演 | 只在**明确完成推演并给出图纸/成果**时申报 `{名称, 档}`；算力不足/推演终止/仅口头设想一律不报；档 1 原始工具 / 2 简单机械 / 3 复杂化工·精细机械 / 4 近代工业 / 5 电气信息；只报档位不扣算力 |
| 9 | 属性成长 | **严禁申报智力**（智力由脚本按时间自动成长：每 10 游戏小时 +1、上限 14）；力/敏 +1：以陷阱/落石/爆破等方式彻底击杀**具名强敌首领**（虚空暴食魔、石像鬼、审判庭精锐猎杀队）；体 +1：濒死（穿胸/断肢/大出血休克）被救回或凭意志撑过极限；普通杂兵、平砍、未写明死亡一律不报 |
| 10 | 生理状态 | `主角状态` 只在持续性负面状态时申报（如"左肩贯穿伤(失血)"）；恢复良好报 `"健康"`；严禁一过性动作或心理 |
| 11 | 精炼管理 | `精练师等级` 只在诺拉现场指导协助下首次完成药剂萃取/料理精炼时报"低级"，只升不降；`临时加成新增` 需正文明确（药剂/战歌，含属性/值/持续分钟/来源），被神术驱散报 `临时加成移除` |
| 12 | 生物管理 | 仅 8 位建档对象；初遇报 `已遇见: true`；`状态` 自由文本（死亡不可逆、不可移出建档）；**属性：仅当正文写明被外力改变时申报、单次 ±1**；异界幼体：陷落度 5/6 且正文中大教堂尖啸降临时才激活 |
| 13 | 同伴关系 | 仅 4 名同伴立场；白名单枚举 路人/相识/熟人/恋人/灵魂的另一半；只在共历生死、深层情感托付时**晋升一级**，严禁跨级 |
| 14 | 提取边界 | 单回合无回滚：只从【本轮待结算正文】提取，严禁从前文重复提取已结算内容 |

## 6. 已知缺口（诚实列出，待修）

| # | 缺口 | 影响 |
|---|---|---|
| 1 | **推演被驳回后无反馈** | AI 不知道算力不够，可能重复报同一次推演（重复驳回无害，但浪费一轮） |
| 2 | **EJS 状态注入条目未做** | 正文AI 目前拿不到系统化的"当前算力/时钟/人物"描述 |
| 3 | **状态栏手操只做了装备穿脱 / 使用消耗品 / 删除物品** | 确认推演、材料加工等玩家主动操作仍无入口；道具的**数值效果**（回血/临时加成）也不会自动施加，需靠正文AI 按 EJS 注入的动作描写 |
| 4 | **智力成长只按时间** | 目前只有"每 10 小时 +1"一条路径（上限 14）；若要"破解真相也加智力"，需在提示词开口子并放开脚本拒收 |

## 7. 一句话总结数据流

正文（AI 写的故事） → **数据AI**（翻译成"变了什么"） → **契约**（zod 校验形状） → **settle**（纯函数按 11 步结算，数字全部脚本算） → **存档**（chat 变量 `艾瑟兰`） → **快照**（stat_data.艾瑟兰，剥内部账本） → **状态栏 / EJS**（只读展示）。
