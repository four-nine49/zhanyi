用户新增需求：**手机版简化状态栏**——「文字 + 简单图形 + 按钮」，不要花哨美术，功能齐全即可。

**新增 3 件 + 修改 3 件：**
1. **`src/gradband/assets/statusbar-mobile.html`**（新，源 ~40KB / dist 76.2KB 含内联引擎）——
   单列卡片流 + 6 页签（🎯槽位 / 📚回路库 / 🛠构筑 / 🧪补给 / ✋手操 / 📜日志），顶部常驻状态条
   （能量/精神双条、身体徽章、战斗旗、爆发/持续线、待扣单数）；回路库页签带 🔔 待送审角标。
   逻辑基底是旧六页（数据读取/writeGame/渲染轮询/构筑核算全套移植），送审是新版补齐的：
   - **剧情送审**（回路库「待送审」牌上直接「⚖ 送审」按钮，无双桌的送审槽拖拽）；
   - **自创申报**（构筑页「⚖ 申报入自由库」）；
   - 两入口共用 `spellReviewBusy()` 互斥 + 令牌 + 超时兜底（送审 15s / 申报 20s）+ 发起即忙碌态
     （render 重绘出禁用按钮/忙碌文案）+ 四路径（通过/驳回/超时/异常）复位——v1.8.6/1.8.7 口径全部带入；
   - 提示词 `getSpellPrompt(kind)` 三层读取链（`法术AI自创/法术AI剧情` → 旧键 `法术AI` → 内联两套兜底），
     json_schema 与双桌逐字一致（自创=效果文字稿无参数向量 / 剧情=必须参数向量）；
   - `参数模板JSON` / `钳制参数` 从双桌版移植（送审填参必需）。

**语义对齐决策（重要）**：
- **手操确认 = 挂待扣单**（`ref=c.id`、`名称+（手操）`、含 workE/分支，回合末 settle ⑥a 统一扣，数据AI 只计次）
  ——与**双桌版**对齐。注意 AGENTS §9.2「操作表确认只扣费不挂单」指的是**扩展侧 `ops-table.ts confirmOps`**
  （工具页手动入口），状态栏自身的确认按钮在双桌版就是挂单语义，手机版跟随主目标。
- **手操每回路每轮一次**（无次数输入），与双桌一致；旧六页的 1~9 次计数未移植。
- **构筑页砍掉了**旧六页的「录入剧情获得的回路（fixed）」和「施放·现构（临时强冲）」——前者与数据AI
  剧情获得→送审链路重复（双桌已无），后者双桌已按用户要求移除。
- 施放（槽位页「⚡ 施放」）= 挂待扣单（ref=`tunedHit||id`、自由回路带「·现构」后缀），同旧六页。
- 构筑页**未移植**双桌的「预设回路免审入库」（chips），手机版所有申报都走法术AI；如需再加。
- 描述框 `S.desc` 在 input 事件即时暂存——4s 轮询重绘不丢字（旧六页有丢字 bug，手机版修了）。
